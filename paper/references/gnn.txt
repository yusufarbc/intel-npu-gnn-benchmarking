# Literatür Tarama Rehberi: Intel Core Ultra NPU Üzerinde GNN Modellerinin Çalıştırılması ve Performans/Enerji Verimliliği Benchmark Analizi

*Araştırmacı Notu: Bu rehber, bilgisayar mimarisi ve makine öğrenmesi araştırmacıları için Intel Core Ultra serisi NPU üzerinde Graph Neural Network (GNN) modellerinin çalıştırılmasına yönelik kapsamlı bir literatür haritası sunmaktadır.*

---

## 1. GNN MODELLERİ VE MİMARİLERİ

### 1.1 Temel GNN Modelleri (Seminal Makaleler)

| Model | Seminal Makale | Yıl | Katkı |
|-------|---------------|-----|-------|
| **GCN** | Kipf & Welling, "Semi-Supervised Classification with Graph Convolutional Networks" [[52]] | 2017 | Spektral tabanlı ilk-order yaklaşım, lokalize filtreleme |
| **GAT** | Veličković et al., "Graph Attention Networks" [[59]][[66]] | 2018 | Attention mekanizması ile komşu ağırlıklandırma |
| **GraphSAGE** | Hamilton et al., "Inductive Representation Learning on Large Graphs" | 2017 | Örnekleme tabanlı endüktif öğrenme |
| **GIN** | Xu et al., "How Powerful are Graph Neural Networks?" [[3]] | 2019 | WL-test eşdeğerliği, güçlü ifade yeteneği |
| **SGC** | Wu et al., "Simplifying Graph Convolutional Networks" | 2019 | Non-lineeritelerin kaldırılması ile hızlandırma |

### 1.2 Hafif/Edge-Uyumlu GNN Varyantları (2022-2025)

- **Degree-Aware Quantization (DAN)** [[120]]: Derece dağılımına duyarlı INT8 quantizasyon ile %1-2 doğruluk kaybı
- **DegreeQuant** [[127]]: GNN'ler için quantization-aware training (QAT) yöntemi, 4.7x latency azalması
- **Aggregation-Aware Quantization** [[118]]: Toplama operatörlerine özel hassasiyet ayarlama
- **Hardware-Aware GNNAS (HGNAS)** [[98]][[102]]: Edge cihazlarda latency ve bellek tahmini ile mimari arama

### 1.3 GNN Operasyonlarının Hesaplama Profili

```
GNN Katmanı = AGGREGATE(⋅) + COMBINE(⋅)

AGGREGATE Fazı:
• Sparse Matrix-Dense Matrix Multiplication (SpMM)
• Irregular memory access pattern (power-law degree distribution)
• Low spatial/temporal locality [[11]]

COMBINE Fazı:
• Dense Matrix-Matrix Multiplication (GEMM)
• Regular computation pattern (MLP benzeri)
• High arithmetic intensity
```

**Araştırma Boşlukları:**
- Sparse-dense hybrid workload'ların NPU'da optimal partitioning stratejileri henüz net değil
- Dynamic graph'lar için streaming inference mimarileri eksik
- Heterojen graph yapılarında (multi-relational) NPU resource allocation stratejileri araştırılmamış

**Yanıtsız Sorular:**
- Intel NPU'nun sparse matrix kernel'leri (CSR/CSC formatları) için native desteği ne düzeyde?
- Graph batching stratejileri NPU memory hierarchy ile nasıl optimize edilmeli?

## 2. NPU VE EDGE AI DONANIM MİMARİLERİ

### 2.1 Genel NPU Mimari Tasarım Felsefesi

| Özellik | Açıklama | GNN Uyumu |
|---------|----------|-----------|
| **Systolic Array** | Dense GEMM için optimize edilmiş [[39]] | COMBINE fazı için uygun |
| **On-chip SRAM Hierarchy** | Off-chip DRAM access latency gizleme | Sparse access pattern'ler için kritik |
| **Low-Precision Arithmetic** | INT8/FP16 native support [[31]] | Quantized GNN inference için ideal |
| **Tile-based Architecture** | Parallelism ve power management [[1]][[4]] | Graph partitioning ile eşleşme potansiyeli |

### 2.2 Intel Core Ultra NPU Mimarisi (Meteor Lake / Lunar Lake)

**Temel Özellikler** [[1]][[2]][[33]]:
- **NCE (Neural Compute Engine)**: Dedicated AI inference accelerator
- **Tile-based Design**: Compute, Graphics, SoC, I/O tiles modular yapı [[10]]
- **ACT-SHAVE Units**: Activation ve normalization için optimize edilmiş hardware
- **Memory Subsystem**: LPDDR5/x support, high-bandwidth on-package memory [[4]]

**OpenVINO NPU Plugin Destekleri** [[31]][[32]][[38]]:
```python
# NPU compilation config örnekleri
config = {
    ov::intel_npu::compilation_mode_params: "optimization-level=2",
    ov::intel_npu::performance-hint-override: "latency",  # veya "efficiency"
    ov::intel_npu::turbo: true  # Max frequency mode (dikkatli kullanım)
}
```

**Sınırlamalar** [[31]]:
- Sadece **static shape** modeller destekleniyor
- Offline compilation blob'ları production için önerilmiyor
- Sparse kernel desteği MKL/oneAPI üzerinden dolaylı

### 2.3 DNN Accelerator'ların GNN için Sınırlılıkları

| Sorun | Neden | Etki |
|-------|-------|------|
| **Sparse Access Inefficiency** | NPU'lar dense tensor ops için optimize [[11]] | SpMM'de düşük utilization |
| **Memory Locality Mismatch** | Power-law degree distribution → irregular access [[14]] | Cache miss rate artışı |
| **Workload Imbalance** | Heterojen node degree'leri [[11]] | PE underutilization |
| **Graph Size Scalability** | On-chip memory sınırları | Large graph'larda frequent off-chip access |

**Araştırma Boşlukları:**
- Intel NPU'nun sparse matrix formatları (CSR, COO) için hardware-level optimizasyonları belgelenmemiş
- Graph-specific dataflow scheduling (vertex-centric vs edge-centric) NPU'da nasıl uygulanır?

**Yanıtsız Sorular:**
- Meteor Lake NPU'da SpMM kernel'lerinin teorik peak performance'u nedir?
- NPU tile'ları arasında graph partitioning ile workload distribution stratejileri neler olabilir?

### 4.2 Graph Sparsity Exploitation

**Stratejiler:**
- **Graph Pruning**: Edge/node removal with accuracy guarantee [[21]]
- **Sparse Format Selection**: CSR vs CSC vs hybrid based on access pattern [[79]][[87]]
- **Dynamic Sparsity**: Runtime adaptive pruning based on input graph [[59]]

**Intel oneAPI Sparse Kernels** [[79]][[87]]:
```cpp

```

### 4.3 Operator Fusion ve Graph Batching

| Teknik | Açıklama | NPU Uyumu |
|--------|----------|-----------|
| **Layer Fusion** | AGGREGATE+COMBINE fusion, memory access azaltma | Yüksek (on-chip buffer friendly) |
| **Graph Batching** | Multiple small graphs → single large batch | Orta (static shape gereksinimi) |
| **Subgraph Sampling** | Neighbor sampling ile computation reduction | Yüksek (edge device için ideal) |

### 4.4 OpenVINO ile GNN Deployment

**Adımlar** [[31]][[128]][[136]]:
1. **Model Export**: PyG/DGL → ONNX (torch.onnx.export ile)
2. **Model Optimization**: 
   ```bash
   ov_convert --input_model model.onnx \
              --compress_to_fp16 \  # veya --quantize INT8
              --output_dir ./ov_model
   ```
3. **NPU Compilation**:
   ```python
   core = ov.Core()
   compiled = core.compile_model(
       model="./ov_model/model.xml",
       device_name="NPU",
       config={ov::intel_npu::performance_hint: "latency"}
   )
   ```

**Bilinen Sorunlar** [[31]]:
- Dynamic shape'lı GNN'ler şu an desteklenmiyor
- Custom GNN operator'leri için fallback to CPU gerekebilir
- Sparse kernel performance'ı dense kernel'lere göre daha düşük

**Araştırma Boşlukları:**
- OpenVINO'nun GNN-specific optimization passes'leri (graph-aware fusion vb.) detaylı belgelenmemiş
- NPU'da graph batching ile throughput scaling davranışı araştırılmamış

**Yanıtsız Sorular:**
- OpenVINO NPU plugin'i hangi GNN operator'lerini native olarak destekliyor?
- Quantization sonrası NPU'da accuracy recovery için fine-tuning stratejileri neler olabilir?

## 1. GNN Modelleri ve Mimarileri

### 1.1 Temel GNN Modelleri (GCN, GAT, GraphSAGE, GIN, SGC)

**Seminal Makaleler:**

- **GCN (Graph Convolutional Network)** – Kipf & Welling (ICLR 2017), spektral graf konvolüsyonunun birinci-derece Chebyshev yaklaşımıyla katman-tabanlı yarı-denetimli öğrenmeyi tanımlar.
- **GAT (Graph Attention Network)** – Veličković et al. (ICLR 2018), düğüm komşularına dinamik ağırlık atayan çok-başlı öz-dikkat mekanizmasını önerir.
- **GraphSAGE** – Hamilton et al. (NeurIPS 2017), tüm komşular yerine sabit-boyutlu örnekleme ile indüktif düğüm gömme öğrenimini mümkün kılar.
- **GIN (Graph Isomorphism Network)** – Xu et al. (ICLR 2019), Weisfeiler-Lehman izomorfizm testi kadar ayırt edici olan teorik çerçeveyi ortaya koyar.
- **SGC (Simplifying Graph Convolutional Networks)** – Wu et al. (ICML 2019), doğrusal olmayan aktivasyonları kaldırarak GCN'yi basit bir lineer modele indirger.

**2022–2025 Güncel Çalışmalar:**

- GNN temel modellerinin sistematik incelemesini sunan kapsamlı derleme çalışmaları (ör. *A review of graph neural networks: concepts, architectures, techniques, challenges, datasets, applications, and future directions*, 2024).
- GNN varyantlarının (GCN, GraphSAGE, GAT, GGNN, HGNN) temel yapıtaşları ve uygulama alanlarına dair Çince literatürdeki güncel derleme çalışmaları.

**Araştırma Boşlukları:**

- Temel GNN modellerinin donanım-özel (özellikle NPU) hesaplama karakterizasyonu yeterince incelenmemiştir.
- Mevcut modellerin NPU üzerindeki darboğaz davranışları (bellek erişim desenleri, paralelleştirme verimliliği) henüz sistematik biçimde belgelenmemiştir.

**Yanıtsız Sorular:**

- Hangi GNN model ailesi (spektral, uzamsal, dikkat-tabanlı) NPU’ların tipik olarak optimize edildiği dense matris işlemlerine en uygun yapıdadır?
- GIN ve GAT gibi karmaşık modellerin NPU üzerindeki doğruluk skorları ile performans arasındaki Pareto-optimal sınır nasıl çizilir?


### 1.2 Hafif / Edge-Uyumlu GNN Varyantları

**Seminal Makaleler:**

- **TinyGNN** – Graf öğrenimini aşırı kaynak-kısıtlı cihazlara taşıyan ilk çalışmalardan.
- **Binary Graph Neural Networks** – Ağırlıkları ve aktivasyonları ikili değerlere indirgeyen erken dönem niceleme yaklaşımları.

**2022–2025 Güncel Çalışmalar:**

- **CiliaGraph** (2024) – Kaynak-kısıtlı edge senaryolarında graf sınıflandırması için hiper-boyutlu hesaplama tabanlı, tek-geçişli ultra-hafif model önerir.
- **HGNAS (Hardware-Aware Graph Neural Architecture Search)** (2024) – Edge cihazlar için ilk donanım-farkında otomatik GNN tasarım çerçevesi olup, farklı platformlarda donanım farkındalığını sağlayan ilk çalışmadır.
- **NE-GConv** (2023) – Saldırı tespit sistemleri için hafif düğüm-kenar graf konvolüsyon ağı önerir.
- **BEAST-GNN** (2026) – Bit-seyrekliği farkında birleşik GNN hızlandırıcı mimarisi.

**Araştırma Boşlukları:**

- Hafif GNN modellerinin Intel NPU özelinde karşılaştırmalı doğruluk-performans analizi eksiktir.
- Edge-uyumlu modellerin NPU üzerindeki enerji verimliliği ölçümleri yapılmamıştır.

**Yanıtsız Sorular:**

- NPU üzerinde hafif GNN modelleri ile tam modeller arasındaki enerji-tasarrufu/doğruluk kaybı dengesi nasıl optimize edilir?
- Donanım-farkında mimari aramanın (HGNAS) Intel NPU hedefiyle entegrasyonu mümkün müdür?


### 1.3 GNN Operasyonlarının Hesaplama Profili (Sparse vs Dense)

**Seminal Makaleler:**

- **SpMM (Sparse-Matrix Dense-Matrix Multiplication)** – GNN toplama fazının temel operasyonu olarak tanımlanmıştır; *VersaGNN* (2021) dense ve sparse matris çarpımını birleştiren ilk sistolik-dizi tabanlı hızlandırıcıdır.
- *Graphite* (GPU tensor çekirdekleri için donanım-farkında GNN yeniden şekillendirme).

**2022–2025 Güncel Çalışmalar:**

- **iSpLib** (2024) – Otomatik ayarlamalı sparse operasyon kütüphanesi ve PyTorch Geometric eklentisi.
- **Cache-Conscious SpMM** (2026) – NVIDIA H100 GPU üzerinde L1 lokalitesini koruyan önbellek-bilinçli zamanlama çerçevesi, GNN türevli sparse matrislerde cuSPARSE’e karşı önemli iyileştirmeler sağlar.
- **SparGNN** (2024) – Algoritma ve hızlandırıcı ortak tasarımı ile özellik ve model seyrekliğini aynı anda kullanan GNN hızlandırma yaklaşımı.

**Araştırma Boşlukları:**

- Intel NPU’nun SpMM performansına dair yayınlanmış bir karakterizasyon çalışması bulunmamaktadır.
- Dense odaklı NPU mimarilerinin sparse graf işlemlerinde ortaya çıkan bellek darboğazları sistematik olarak incelenmemiştir.

**Yanıtsız Sorular:**

- NPU’lardaki sistolik dizi mimarisi, graf işlemlerinin sparse doğasıyla nasıl başa çıkar?
- Sparse graf verileri NPU’ya beslenmeden önce hangi düzeyde yoğunlaştırma (densification) yapılmalıdır?

## 2. NPU ve Edge AI Donanım Mimarileri

### 2.1 Genel NPU Mimarileri ve Tasarım Felsefesi

**Seminal Makaleler:**

- NPU tasarım felsefesinin üç ana kategoriye ayrıldığı genel çerçeve: (i) verimlilik-odaklı, (ii) performans-odaklı, (iii) esneklik-odaklı.
- Sistolik dizi, vektör/SIMD motorları, özel dikkat/softmax çekirdekleri, niceleme-farkında veriyolları ve yüksek bant genişliğine sahip bellek hiyerarşilerini sentezleyen kapsamlı donanım hızlandırma derlemesi (2026).

**2022–2025 Güncel Çalışmalar:**

- NPU’ların teknik arka plan, prensipler, gelişim patikası, temel performans metrikleri ve büyük dil modelleriyle entegrasyonuna dair yedi boyutlu panoramik analiz (2026).
- Cihaz-üstü eğitim için NPU algoritma-mimari-SoC tasarımına odaklanan monografiler.
- Modern NPU üzerinde nedensel çıkarım operatörlerinin bağlam-güdümlü performans modellemesi.

**Araştırma Boşlukları:**

- NPU tasarım felsefelerinin GNN iş yüklerine uygunluğu henüz irdelenmemiştir.
- NPU’nun Veri Yolu Birimi (DPU) içindeki İşlem Elemanı (PE) dizisinin graf tabanlı düzensiz hesaplamalar için uygunluğu belirsizdir.

**Yanıtsız Sorular:**

- Mevcut NPU mimarileri (özellikle Intel NPU 3/4) GNN’lerin gerektirdiği haberleşme-yoğun (message-passing) paradigmaya ne ölçüde uyumludur?
- NPU’larda GNN hızlandırma için özel bir komut seti veya mikro-mimari uzantı gerekli midir?


### 2.2 Intel Core Ultra NPU Mimarisi (Meteor Lake / Lunar Lake)

**Teknik Özellikler:**

- **Meteor Lake (NPU 3):** ~11 TOPS yapay zekâ performansı; Intel’in monolitik silikondan ayrıştırılmış MCM tasarımına geçişini temsil eder.
- **Lunar Lake (NPU 4):** NPU 3’e kıyasla 3 kat performans artışı ve 48 TOPS’a ulaşan toplam NPU kapasitesi; 6 adet Neural Compute Engine (NCE) çekirdeği içerir; platform toplamı 120 TOPS’a ulaşır.
- **Panther Lake (NPU 5):** ~50 TOPS civarında performansı koruyarak optimize edilmiştir.

**2022–2025 Güncel Çalışmalar:**

- Lunar Lake’in TSMC 3 nm süreciyle üretilen hesaplama döşemesi, entegre bellek ve Xe2 tabanlı GPU’ya dair teknik incelemeler.
- Lunar Lake’in Microsoft Copilot+ standardı için gereken 40+ TOPS eşiğini karşılayan ilk Intel platformu olduğu vurgulanmaktadır.

**Araştırma Boşlukları:**

- Intel NPU 3 ve NPU 4’ün GNN iş yükleri için detaylı performans/enerji ölçümleri yayınlanmamıştır.
- NPU’nun OpenVINO ve DirectML gibi yazılım yığınları üzerinden GNN desteği dokümante edilmemiştir.

**Yanıtsız Sorular:**

- Intel NPU’nun NCE çekirdek sayısı ile GNN katman sayısı arasındaki ölçeklenme ilişkisi nasıldır?
- NPU 4’ün 48 TOPS kapasitesi, GNN çıkarımı için hangi model/graf büyüklüklerinde CPU veya GPU’ya kıyasla avantaj sağlar?


### 2.3 DNN Accelerator’ların GNN için Sınırlılıkları

**Seminal Makaleler:**

- GNN’lerin graf işleme ve DNN iş yüklerinin bir hibridi olduğu, DNN tabanlı özellik çıkarıcıları ile graf dolaşımını birleştirdiği temel tespiti (2021).

**2022–2025 Güncel Çalışmalar:**

- GraNNite – DNN hızlandırıcılar üzerinde GNN yürütmenin temel zorluklarını (seyreklik yönetimi, düzensiz bellek erişimi, mesaj-iletim paradigmaları) ele alan ilk donanım-farkında çerçeve.
- **I-DGNN** (2025) – Dinamik GNN’ler için ölçeklenebilir hızlandırıcı tasarım çerçevesi, enerji verimliliği ve performans iyileştirmeleri sunar.

**Araştırma Boşlukları:**

- DNN hızlandırıcıların GNN’lerdeki graf-tabanlı toplama (aggregation) fazındaki verimsizliklerinin nicel analizi eksiktir.
- COTS DNN hızlandırıcıların GNN eğitimi (sadece çıkarım değil) için uygunluğu araştırılmamıştır.

**Yanıtsız Sorular:**

- NPU’ların yoğun matris çarpımına optimize edilmiş yapısı, GNN toplama fazındaki sparse-dense matris çarpımında ne kadar verim kaybına yol açar?
- NPU bellek hiyerarşisi (scratchpad, L1/L2) graf verilerinin düzensiz erişim desenlerine uyarlanabilir mi?

## 3. GNN Donanım Hızlandırma

### 3.1 FPGA Tabanlı GNN Accelerator’lar

**Seminal Makaleler:**

- FPGA üzerinde GNN hızlandırmaya dair ilk sistematik derleme: niceleme ve FPGA tabanlı GNN hızlandırma arasındaki etkileşimi inceler.

**2022–2025 Güncel Çalışmalar:**

- Son 6 yılda 1138 makale arasından seçilen 287 FPGA tabanlı ML hızlandırıcı makalesinin kapsamlı derlemesi (4 büyük FPGA konferansından).
- **H-GCN** (2022) – Xilinx Versal ACAP üzerinde PL (Programlanabilir Mantık) ve AIE (AI Engine) hibrit GCN hızlandırıcısı.

**Araştırma Boşlukları:**

- FPGA ile Intel NPU arasında GNN çıkarımı için doğrudan karşılaştırmalı çalışma bulunmamaktadır.
- FPGA üzerindeki GNN hızlandırıcılarının geliştirme süresi ve esneklik avantajı, NPU’nun üstün performansı ile kıyaslanmamıştır.

**Yanıtsız Sorular:**

- FPGA tabanlı GNN hızlandırma ile NPU tabanlı yaklaşımlar arasındaki performans/watt kesişim noktası nerededir?
- FPGA’nın yeniden yapılandırılabilirliği, GNN modellerinin NPU’ya kıyasla daha verimli çalıştırılmasını sağlayabilir mi?


### 3.2 ASIC Tabanlı GNN Accelerator’lar

**Seminal Makaleler:**

- **NeuraChip** – Gustavson algoritmasına dayalı, çarpma ve toplama işlemlerini ayrıştıran özgün GNN uzamsal hızlandırıcısı; seyrek matris çarpımında önbellek verimsizliğini giderir.
- Çok çekirdekli GNN eğitim hızlandırıcısı – 8.6 milyon düğüme kadar büyük veri kümelerini işleyebilen ölçeklenebilir ASIC tasarımı (önceki FPGA/ASIC GNN hızlandırıcılarına kıyasla önemli ilerleme).

**2022–2025 Güncel Çalışmalar:**

- AMD Versal ACAP üzerinde GNN çıkarımını hızlandırmak için dinamik seyreklikten yararlanan heterojen hesaplama yaklaşımı (2023).

**Araştırma Boşlukları:**

- ASIC GNN hızlandırıcılarla Intel NPU arasında kıyaslama çalışması bulunmamaktadır.
- ASIC GNN hızlandırıcılarda kullanılan özel bellek hiyerarşilerinin NPU’daki karşılığı analiz edilmemiştir.

**Yanıtsız Sorular:**

- ASIC GNN hızlandırıcıların sipariş üzerine tasarlanan mimari avantajları, COTS NPU’ların yazılım optimizasyonlarıyla ne ölçüde kapatılabilir?
- GraNNite gibi yazılım çerçeveleri, NPU’ları ASIC-benzeri GNN performansına yaklaştırabilir mi?


### 3.3 COTS (Commercial Off-The-Shelf) Cihazlarda GNN

**Seminal Makaleler:**

- GNN’lerin COTS cihazlarda dağıtımı (deployment) üzerine erken çalışmalar; genellikle CPU/GPU üzerinde yoğunlaşmıştır.

**2022–2025 Güncel Çalışmalar:**

- **GraNNite** – COTS SOTA DNN hızlandırıcılar üzerinde GNN dağıtımını optimize eden ilk donanım-farkında çerçeve; üç aşamalı metodoloji: NPU yürütmeyi etkinleştirme, performans optimizasyonu, doğruluk-verimlilik dengesi.
- **GCoDE** (2024) – Cihaz-edge ortak çıkarım sistemleri için GNN otomatik tasarım ve dağıtım çerçevesi, mimari aramayı ve operasyon haritalamayı birleştirir.
- **ChainNet** (2024) – Edge AI servis dağıtımı için kayıp-farkında GNN modeli.

**Araştırma Boşlukları:**

- COTS cihazlarda GNN çıkarımı için standart bir benchmark suite bulunmamaktadır.
- Farklı COTS platformlar (Intel NPU, Apple Neural Engine, Qualcomm Hexagon) arasında GNN performansı karşılaştırması yapılmamıştır.

**Yanıtsız Sorular:**

- COTS cihazlardaki NPU’lar, GNN çıkarımı için hangi model karmaşıklık seviyesine kadar CPU/GPU’dan daha verimlidir?
- GraNNite’ın metodolojisi farklı NPU mimarileri için genelleştirilebilir mi?


### 3.4 NPU Üzerinde GNN (GraNNite ve Benzeri Çalışmalar)

**GraNNite Detaylı İnceleme:**

- **Yayın:** 2025, arXiv / Intel Labs.
- **Üç aşamalı metodoloji:**
  1. NPU haritalamayı etkinleştirme ve dinamik graf işlemeyi iyileştirme
  2. Performans optimizasyonu
  3. Doğruluk-verimlilik dengesi: QuantGr (INT8 niceleme) ve GrAx1/GrAx2/GrAx3 (dikkat, broadcast-add, SAGE-max toplama hızlandırma).
- **Donanım platformu:** Intel Core Ultra AI PC’ler üzerinde test edilmiştir.
- Intel tarafından resmî olarak tanıtılan GraNNite: "olağanüstü performans ve verimlilik" vurgusu.

**Araştırma Boşlukları:**

- GraNNite’ın yalnızca Intel NPU üzerinde test edilmiş olması; diğer NPU platformlarına (Qualcomm, Apple, Samsung) taşınabilirliği belirsizdir.
- GraNNite’ın GNN eğitimi için uygunluğu (sadece çıkarım değil) dokümante edilmemiştir.
- Çok büyük ölçekli graflarda (milyonlarca düğüm) GraNNite’ın bellek ölçeklenebilirliği incelenmemiştir.

**Yanıtsız Sorular:**

- GraNNite’ın optimizasyon stratejileri (özellikle QuantGr ve GrAx operasyonları), gelecek nesil Intel NPU mimarilerinde (NPU 4 ve NPU 5) nasıl performans gösterir?
- GraNNite, GNN model eğitimi için de uyarlanabilir mi?

## 4. Deployment ve Optimizasyon Teknikleri

### 4.1 Model Quantization (INT8, FP16) GNN için

**Seminal Makaleler:**

- **Degree-Quant (DBQ)** – Graf yapısındaki hassas düğümleri tanımlayan derece-tabanlı niceleme; INT8 için FP32 ile eşdeğer performans, INT4 için %26’ya varan kazanç sağlar.
- **DBQ for GNN** (2022) – Duyarlı düğümler için koruyucu maskelerle tam hassasiyet, kalan düğümler için niceleme.

**2022–2025 Güncel Çalışmalar:**

- FP16, INT8, INT4 ve INT2 niceleme seviyelerinin GNN modelleri üzerindeki etkilerini karşılaştıran deneysel çalışma; INT8’in tam hassasiyetle eşdeğer performansı koruduğu, INT2’nin önemli performans düşüşüne yol açtığı raporlanmıştır (2025).
- **Yaklaşıklık- ve Niceleme-Farkında Eğitim** (2024) – GNN’ler için ilk kez her iki optimizasyonu birleştiren eğitim yaklaşımı.

**Araştırma Boşlukları:**

- INT8 niceleme ile NPU’nun doğal niceleme desteği (ör. Intel NPU’nun INT8 çıkarım hızlandırması) arasındaki sinerji detaylıca incelenmemiştir.
- GNN niceleme sırasında graf yapısının (topoloji) korunması ile niceleme hatalarının ilişkisi modellenmemiştir.

**Yanıtsız Sorular:**

- NPU üzerindeki GNN niceleme hataları, hangi graf topolojilerinde (yoğun vs. seyrek, homofilik vs. heterofilik) daha belirgindir?
- INT4 ve daha düşük hassasiyet seviyeleri NPU’da kullanılabilir mi?


### 4.2 Graph Sparsity Exploitation

**Seminal Makaleler:**

- **Graph Sparse Training (GST)** – Veri seviyesinde seyrekliği dinamik olarak manipüle eden yeni araştırma hattı.

**2022–2025 Güncel Çalışmalar:**

- **SparGNN** (2024) – Hem özellik hem de model seyrekliğini aynı anda kullanan algoritma-hızlandırıcı ortak tasarımı.
- **Sparse Sobolev GNN (S2-GNN)** (2025) – Hadamard çarpımlarıyla graf temsillerinde seyreklik seviyesini koruyan yüksek-dereceli GNN.
- **Two Heads Are Better Than One** (2024) – Semantik ve topolojik farkındalıkla graf seyrek eğitimini hızlandırma.

**Araştırma Boşlukları:**

- Graf seyrekliğinin NPU üzerindeki hesaplama ve bellek erişim avantajları nicel olarak gösterilmemiştir.
- Seyreklik oranı ile NPU performansı arasındaki ilişki (hangi seyreklik eşiğinde NPU avantajı kaybolur?) belirsizdir.

**Yanıtsız Sorular:**

- Seyrek graf verilerini NPU’nun dense-optimize edilmiş işlem birimlerine beslemenin optimal stratejisi nedir?
- Graf seyrekliği, NPU’nun bellek hiyerarşisinde hangi seviyede en büyük avantajı sağlar?


### 4.3 Operator Fusion ve Graph Batching

**Seminal Makaleler:**

- **GNN Computational Graph Optimization** (2021) – Operatör füzyonu, yayılım-ertelenmiş operatör reorganizasyonu ile %92.4’e varan gereksiz operatör hesabını ortadan kaldırır.

**2022–2025 Güncel Çalışmalar:**

- **FuseSampleAgg** (2025) – GraphSAGE için komşu örnekleme ve ortalama toplamayı tek bir CUDA çekirdeğinde birleştiren operatör.
- **Partition-level Operator Fusion** (2025) – Bölüm-seviyesinde operatör füzyonu ve çoklu iş parçacığı ile GNN bant genişliği gereksinimlerini azaltır.
- **BLAD** (SC23) – Dinamik GNN eğitimi için uyarlanabilir yük dengelemeli zamanlama ve operatör örtüşme hattı.

**Araştırma Boşlukları:**

- Operatör füzyonunun NPU’ya özgü derleyici optimizasyonları (örn. OpenVINO graph compilation) ile entegrasyonu yapılmamıştır.
- NPU üzerindeki mini-batch GNN eğitimi için optimal batch büyüklüğü ve füzyon stratejisi belirlenmemiştir.

**Yanıtsız Sorular:**

- NPU’nun sabit işlem hattı, dinamik operatör füzyonu stratejilerine ne ölçüde izin verir?
- OpenVINO’nun graf derleme aşamasında GNN’ye özgü operatör füzyonu kuralları uygulanabilir mi?


### 4.4 OpenVINO ile GNN Deployment

**Mevcut Durum:**

- OpenVINO, Intel donanımlarında derin öğrenme modellerini dağıtmak için model optimizasyonu, niceleme ve graf optimizasyonu araçları sunar.
- OpenVINO Model Server, Directed Acyclic Graph (DAG) tabanlı işlem hatları oluşturmaya olanak tanır.
- nGraph Core, Inference Engine altında CNNNetwork API’si ile modellerin çalışma zamanı temsilini yönetir.

**2022–2025 Güncel Çalışmalar:**

- OpenVINO’nun bilgi grafı gömme modelleri (ConvE) için optimize edilmiş çıkarım performansı demo çalışması.
- oneDNN ile OpenVINO performans entegrasyonu, ayrık GPU’larda en iyi performansı hedefler.

**Araştırma Boşlukları:**

- OpenVINO’nun GNN’ye özgü model temsil formatı veya operasyon seti desteği dokümante edilmemiştir.
- OpenVINO’nun graf derleme aşamasında GNN operatörleri (SpMM, Scatter/Gather, Attention) için özel optimizasyon eksikliği vardır.

**Yanıtsız Sorular:**

- OpenVINO, PyTorch Geometric veya DGL’den dönüştürülen GNN modellerini doğrudan destekleyecek şekilde genişletilebilir mi?
- OpenVINO’nun mevcut graf optimizasyonu altyapısı, GNN operatör füzyonu için yeterli midir?

## 5. Benchmark Metodolojisi

### 5.1 Donanım Benchmark Metodolojileri

**Seminal Makaleler:**

- **CARAML** – Transformer tabanlı LLM'ler ve bilgisayarla görü modelleri için donanım hızlandırıcılarda performans ve enerji tüketimini değerlendiren benchmark suite'i (NVIDIA, AMD, Graphcore).

**2022–2025 Güncel Çalışmalar:**

- **ML.ENERGY Benchmark** (2025) – Gerçekçi servis ortamlarında çıkarım enerji tüketimini ölçmek için benchmark suite ve araç; ML.ENERGY Leaderboard.
- **Intelligence Per Watt (IPW)** (2025) – Stanford Üniversitesi: Görev doğruluğunu güç birimi başına ölçen, 20+ model ve 8 donanım hızlandırıcıyı kapsayan metrik.
- **LEAF (LLM Edge Assessment Framework)** (2026) – Edge dağıtımlarını beş boyutta değerlendirir: döngüsel ekonomi skoru, enerji verimliliği, performans hızı, semantik doğruluk.

**Araştırma Boşlukları:**

- GNN’ye özgü donanım benchmark metodolojisi standardı mevcut değildir.
- IPW gibi birleşik metriklerin GNN bağlamında uyarlanması yapılmamıştır.

**Yanıtsız Sorular:**

- GNN çıkarımı için "Intelligence per Watt" benzeri bir metrik nasıl tanımlanmalıdır?
- Donanım benchmark’larında GNN’ye özgü metrikler (düğüm/graft başına enerji, toplama fazı verimliliği) gerekli midir?


### 5.2 GNN Inference Benchmark Çalışmaları

**Seminal Makaleler:**

- **gSuite** – GPU’lar üzerinde GNN çıkarımı için esnek ve çerçeve-bağımsız benchmark suite; mimari GPU simülatörleri ve profilleyicilerle detaylı performans karakterizasyonu sağlar.

**2022–2025 Güncel Çalışmalar:**

- **GNN-Suite** (2025) – Biyomedikal enformatik için modüler GNN benchmark çerçevesi; Nextflow iş akışı ve dengeli doğruluk (BACC) birincil metrik olarak kullanılır.
- **GNNEvaluator** (2023/2025) – Etiketsiz graflarda GNN performansını değerlendiren iki aşamalı çerçeve (DiscGraph + GNNEvaluator).
- **DyGEval** (2025) – Dinamik graflar için test-zamanı DGNN değerlendiricisi.
- Graf sınıflandırma benchmark’larının yeniden değerlendirilmesi ve adil kıyaslama protokolü (IJCAI 2024).

**Araştırma Boşlukları:**

- GNN-Suite ve gSuite gibi çerçeveler NPU destekli cihazlarda test edilmemiştir.
- GNN çıkarım benchmark’ları genellikle doğruluk metriklerine odaklanır; enerji ve gecikme metrikleri ihmal edilir.

**Yanıtsız Sorular:**

- NPU üzerinde GNN benchmark için minimum gerekli metrik seti (doğruluk, gecikme, enerji, bellek) nasıl standardize edilir?
- Graf büyüklüğü ve yoğunluğu ile NPU performansı arasındaki ilişki nasıl modellenir?


### 5.3 Enerji Verimliliği Ölçüm Yöntemleri

**Seminal Makaleler:**

- Birleşik ve yeniden üretilebilir AI çıkarım enerji ölçüm metodolojisi: gecikme, iş çıkarma (throughput), enerji tüketimi ve konuma göre ayarlanmış karbon emisyonlarını entegre eder (2025).

**2022–2025 Güncel Çalışmalar:**

- Edge GPU’lar için ML-tabanlı performans modelleme çerçevesi – çıkarım gecikmesi ve enerji tüketimini aynı anda tahmin eder (2025).
- **ML.ENERGY Benchmark** ile otomatik çıkarım enerji ölçümü (2025).

**Araştırma Boşlukları:**

- Intel NPU’nun enerji tüketimini doğrudan ölçen araçların (örn. Intel SoC Watch, RAPL) GNN iş yükleri için validasyonu yapılmamıştır.
- NPU’nun idle ve aktif durum enerji profili GNN bağlamında karakterize edilmemiştir.

**Yanıtsız Sorular:**

- NPU üzerinde GNN çıkarımı için enerji tüketimini doğru ölçmek üzere hangi araçlar ve API’ler kullanılmalıdır?
- NPU’nun düşük güç modu ile performans modu arasında GNN çıkarımı için enerji-gecikme dengesi nasıl optimize edilir?


### 5.4 MLPerf ve Benzeri Standart Benchmark’lar

**Seminal Makaleler:**

- **MLPerf Inference: Edge** – Sistemlerin eğitilmiş modellerle ne kadar hızlı çıkarım yapabildiğini ölçen endüstri standardı; SPEC sertifikalı güç ölçüm standartları.
- **MLPerf Inference v5.0** (2025) – 23 kuruluşun katılımıyla en güncel sonuçlar; Llama 2 70B için düşük gecikmeli çıkarım senaryoları içerir.

**Araştırma Boşlukları:**

- MLPerf Edge benchmark suite şu anda GNN iş yüklerini içermemektedir.
- MLPerf’in güç ölçüm metodolojisi NPU-özel senaryolara uyarlanmamıştır.

## 1. GNN MODELLERİ VE MİMARİLERİ

### Seminal (Kurucu) Makaleler

| Model | Yıl | Yazar(lar) | Katkısı |
|-------|-----|-----------|---------|
| **GCN** (Graph Convolutional Network) | 2016 | Kipf & Welling | Spektral graph convolution'ın ilk başarılı uygulaması; komşu özelliklerin ortalamasını alan message passing paradigmasını kurdu |
| **GAT** (Graph Attention Network) | 2017 | Veličković et al. | Self-attention mekanizmasını graph'lara taşıdı; farklı komşulara farklı ağırlıklar atama yeteneği |
| **GraphSAGE** | 2017 | Hamilton et al. | Inductive learning'i mümkün kıldı; komşu örnekleme (sampling) ile büyük ölçekli graph'lar için çözüm |
| **GIN** (Graph Isomorphism Network) | 2018 | Xu et al. | Weisfeiler-Lehman testi ile teorik olarak en güçlü sınıflandırıcı olduğunu kanıtladı |
| **SGC** (Simplified Graph Convolution) | 2019 | Wu et al. | Non-lineerlikleri kaldırarak GCN'i lineer modele indirgedi; hesaplama verimliliğini artırdı |

### Güncel Çalışmalar (2022-2025)

- **Lightweight/Edge-Uyumlu Varyantlar**: Düşük bellek ve hesaplama gereksinimleri için tasarlanmış GNN varyantları geliştirilmeye devam ediyor. GraphSAGE'in komşu örnekleme mekanizması, edge cihazlarda bellek kısıtlamalarını hafifletmek için kritik öneme sahiptir .

- **Quantization-Aware GNN Eğitimi**: Tailor et al. (2020) tarafından önerilen Degree-Quant (DQ) tekniği, GNN'lerde INT8 quantization için seminal bir çalışmadır. Düğüm derecesine (degree) bağlı olarak farklı scale parametreleri kullanarak, GAT ve GIN modellerinde FP32'e yakın doğruluk elde edilmiştir .

### GNN Operasyonlarının Hesaplama Profili

GNN'ler iki temel operasyon içerir:
1. **Sparse Operasyonlar**: Komşu toplama (neighbor aggregation) - adjacency matrix ile özellik vektörlerinin çarpımı; düzensiz bellek erişimi (irregular memory access) pattern'ine sahiptir.
2. **Dense Operasyonlar**: Özellik dönüşümü (feature transformation) - standart matris çarpımları; düzenli ve yüksek paralellik potansiyeline sahiptir.

Bu dualite, GNN'lerin donanım hızlandırılmasını karmaşıklaştırır: Sparse kısım bellek-bağımlı (memory-bound), dense kısım ise hesaplama-bağımlı (compute-bound) karakterdedir .

### Araştırma Boşlukları

- **Edge-Özel GNN Mimarileri**: Mevcut GNN modelleri genellikle GPU/veri merkezi ortamı için optimize edilmiştir. NPU'nun vektör işlem birimleri ve sınırlı bellek bant genişliği için özel tasarlanmış GNN varyantları neredeyse hiç yoktur.
- **Dinamik Graph'lar**: Çoğu çalışma statik graph'lar üzerindedir. Edge cihazlarda karşılaşılan dinamik, zamanla değişen graph yapıları için GNN modelleri ve optimizasyon teknikleri yetersizdir.
- **Yanıtsız Sorular**: GAT gibi attention mekanizması içeren modellerin NPU üzerindeki performansı nasıldır? Attention skorlarının hesaplanması NPU'nun vektör birimleri için uygun mudur?

## 2. NPU VE EDGE AI DONANIM MİMARİLERİ

### Genel NPU Mimarileri ve Tasarım Felsefesi

NPU'lar (Neural Processing Unit) AI iş yükleri için özel olarak tasarlanmış donanım hızlandırıcılardır. Temel tasarım felsefesi:
- **Düşük Hassasiyet Aritmetiği**: INT8/FP16 gibi düşük bit genişliklerinde yüksek verimlilik
- **Yüksek Bellek Bant Genişliği**: Veri hareketini minimize etmek için yüksek bant genişlikli bellek alt sistemleri
- **Verimli DMA (Direct Memory Access)**: Veri taşıma operasyonlarının hesaplama ile örtüşmesi 

### Intel Core Ultra NPU Mimarisi

#### Meteor Lake (Seri 1) - NPU 3
- **Mimari**: Tile-tabanlı tasarım; CPU, GPU ve NPU ayrı tile'larda
- **NPU Yetenekleri**: 10 INT8 TOPS
- **İşlem Teknolojisi**: Intel 4
- **Özellikler**: Yapay zeka iş yüklerini yerel olarak, düşük güç tüketimiyle işleme yeteneği 

#### Lunar Lake (Seri 2) - NPU 4
- **Mimari**: NPU 4 mimarisi; önceki nesle göre köklü değişiklikler
- **Performans**: 48 INT8 TOPS (NPU tek başına); toplam sistem 120 TOPS (CPU+GPU+NPU)
- **Vektör İşlem**: SHAVE DSP birimleri 4x vektör işlem kapasitesi artışı; toplam 12x vektör performansı iyileştirmesi
- **DMA**: 2x DMA bant genişliği artışı
- **MAC Array**: 2048 MAC/cycle (INT8), 1024 MAC/cycle (FP16)
- **Microsoft Copilot+ PC Sertifikasyonu**: 40 TOPS minimum gereksinimini karşılar 

Intel'in NPU 4'teki temel iyileştirmeler:
1. **Vektör İşlem Vurgusu**: Transformer ve LLM iş yükleri için vektör işlem kapasitesi artırıldı
2. **Sistem Belleği Bağımlılığının Azaltılması**: Daha fazla verinin NPU içindeki scratchpad bellekte tutulması
3. **Gömülü Tokenizasyon**: Embedding ve tokenizasyon işlemleri için donanım desteği 

### DNN Accelerator'ların GNN İçin Sınırlılıkları

NPU'lar temel olarak dense matris çarpımları (GEMM) ve evrişim (convolution) için optimize edilmiştir. GNN'lerin temel zorlukları:

1. **Düzensiz Bellek Erişimi**: Graph'ların sparse adjacency matrix yapısı, NPU'nun düzenli veri erişim pattern'lerine aykırıdır 
2. **Dinamik Komşuluk**: Her düğümün farklı sayıda komşusu olması, NPU'nun statik programlama modeliyle çatışır
3. **Küçük Matris Boyutları**: GNN katmanları genellikle küçük matris çarpımları içerir; NPU'lar büyük matrisler için optimize edilmiştir 
4. **Gather-Scatter Operasyonları**: Graph toplama (aggregation) işlemleri, NPU'nun tipik inference pipeline'ından farklı bir hesaplama pattern'i gerektirir 

### Araştırma Boşlukları

- **NPU İçin Graph-Özel İşlem Birimleri**: Mevcut NPU'lar graph operasyonlarını (özellikle sparse matrix multiplication) doğrudan desteklememektedir. Graph-specific instruction set extensions araştırılmamıştır.
- **Heterojen İş Yükü Dağıtımı**: CPU-GPU-NPU üçlüsü arasında GNN inference'ın dinamik olarak bölünmesi (örneğin sparse kısım CPU'da, dense kısım NPU'da) yeterince incelenmemiştir.
- **Yanıtsız Sorular**: Lunar Lake'in 12x artan vektör performansı, GNN'lerin sparse operasyonlarına nasıl yansır? NPU 4'ün yeni DMA motoru, graph'ların düzensiz bellek erişim pattern'ini ne ölçüde iyileştirebilir?

## 4. DEPLOYMENT VE OPTİMİZASYON TEKNİKLERİ

### Model Quantization (INT8, FP16) GNN İçin

Quantization, GNN'lerin edge cihazlarda çalıştırılması için kritik bir tekniktir:

- **Degree-Quant (DQ)**: Tailor et al. tarafından önerilen bu teknik, GNN'lerde düğüm derecesine bağlı quantization scale parametreleri kullanır. Sonuçlar:
  - GCN-INT8: %81.7 doğruluk (FP32: %80.9) - *hafif iyileşme*
  - GAT-INT8: %82.1 doğruluk (FP32: %82.3)
  - GIN-INT8: %77.2 doğruluk (FP32: %77.9) 

- **Intel Neural Compressor**: Intel'in otomatik quantization aracı, GNN mimarileri için özel olarak ayarlanmıştır. Model sıkıştırma oranı 4:1, doğruluk kaybı %1'in altında .

- **FP16 vs INT8**: Lunar Lake NPU 4, hem FP16 (1024 MAC/cycle) hem de INT8 (2048 MAC/cycle) destekler. INT8, 2x daha yüksek teorik throughput sunar .

### Graph Sparsity Exploitation

- **Sparse Neighbor Aggregation**: GPU Tensor Core'ları üzerinde sparse-dense matris çarpımı için optimizasyon teknikleri geliştirilmiştir . Ancak bu teknikler NPU'ya henüz uyarlanmamıştır.
- **Graph Sparsity Patterns**: Farklı graph türlerinin (sosyal ağlar, moleküler graph'lar, öneri sistemleri) sparsity özelliklerine göre optimizasyon stratejileri farklılık gösterir.

### Operator Fusion ve Graph Batching

- **AlphaGNN** (2025): Hesaplama graph'ı ve operatör optimizasyonlarını koordineli bir strateji ile birleştiren yaklaşım. Sub-graph fusion mekanizmaları ile kernel launch overhead'ini azaltma ve bellek erişim optimizasyonu .
- **Fusion Kuralları**:
  - Hesaplama-yoğun operatörler (dense matris çarpımı) fusion'a katılamaz
  - Scatter-Gather operasyonları fusion için uygundur
  - Boş (empty) Scatter operasyonları, sonraki ApplyEdge ile fusion edilebilir 

### OpenVINO ile GNN Deployment

Intel OpenVINO, GNN modellerinin Intel donanımı üzerinde deploy edilmesi için ana araçtır:

- **Workflow**:
  1. PyTorch/PyG ile model eğitimi
  2. ONNX formatına dönüştürme
  3. OpenVINO IR formatına optimizasyon
  4. CPU/GPU/NPU üzerinde inference 

- **Optimizasyonlar**:
  - Graph-level optimizasyonlar (node fusion, memory layout transformations)
  - %40-70 inference latency azaltma (mobil CPU'lerde) 
  - Adaptive graph sampling algoritmaları

### Araştırma Boşlukları

- **NPU-Özel Fusion Kuralları**: Mevcut fusion çalışmaları GPU için yapılmıştır. NPU'nun farklı bellek hiyerarşisi ve işlem pipeline'ı için özel fusion kuralları geliştirilmemiştir.
- **Dynamic Batching**: Graph'ların dinamik boyutları, NPU için statik batching stratejilerini zorlaştırır. Graph-specific dynamic batching teknikleri yetersizdir.
- **Yanıtsız Sorular**: OpenVINO'nun GNN optimizasyonları, NPU 4'ün yeni vektör birimlerinden tam olarak nasıl yararlanır? INT8 quantization sonrası GNN modellerinin NPU üzerindeki doğruluk kaybı sistematik olarak incelenmiş midir?

### Edge Cihazlarda AI Inference Karşılaştırmaları

- **Heterojen Hesaplama Stratejileri**: 
  - NPU: Küçük batch, bellek-bağımlı iş yükleri için ideal
  - GPU: Büyük batch, hesaplama-bağımlı iş yükleri için ideal
  - CPU: Basit, düşük paralellikli operasyonlar için ideal 

- **GraNNite NPU Sonuçları**: Intel Core Ultra NPU üzerinde GCN, GAT ve GraphSAGE modelleri, CPU ve GPU ile karşılaştırıldığında enerji verimliliği açısından üstün performans göstermiştir. Ancak mutlak latency değerleri henüz yayınlanmamıştır .

### Araştırma Boşlukları

- **GNN-Özel Karşılaştırma**: Mevcut karşılaştırmalar genel DNN modelleri (CNN, LLM) üzerinedir. GNN'ler için kapsamlı CPU-GPU-NPU karşılaştırması sadece GraNNite ile sınırlıdır ve bu çalışma da sınırlı dataset'ler üzerindedir.
- **Ölçeklenebilirlik Analizi**: Graph boyutu (düğüm ve kenar sayısı) arttıkça NPU'nun göreceli performansı nasıl değişir? Bu kritik soru yanıtsızdır.
- **Heterojen İş Yükü Dağılımı**: GNN inference'ının farklı katmanlarının CPU, GPU ve NPU arasında dinamik olarak dağıtılması için otomatik karar mekanizmaları geliştirilmemiştir.
- **Yanıtsız Sorular**: 
  - NPU, hangi graph boyutu aralığında GPU'dan daha verimlidir?
  - Multi-head attention içeren GAT modelleri, NPU'nun vektör birimlerinden faydalanabilir mi?
  - GraphSAGE'in komşu örnekleme mekanizması, NPU'nun deterministik pipeline'ı ile nasıl uyum sağlar?

## GENEL ARAŞTIRMA BOŞLUKLARI VE YÖNELİM ÖNERİLERİ

### En Kritik Araştırma Boşlukları

1. **NPU için Graph-Native Operatör Desteği**: Mevcut NPU'lar dense matris operasyonları için tasarlanmıştır. Sparse graph operasyonlarını (gather-scatter, sparse matrix multiplication) donanım seviyesinde destekleyen NPU mimarileri araştırılmalıdır.

2. **Endüstriyel Ölçekli Benchmark'lar**: GraNNite gibi çalışmalar sadece akademik dataset'ler (Cora, Citeseer) üzerindedir. Milyonlarca düğüm içeren endüstriyel graph'lar (sosyal ağlar, öneri sistemleri, fraud detection) için NPU benchmark'ları kritik öneme sahiptir.

3. **GNN-Özel Quantization Teknikleri**: Mevcut quantization çalışmaları genel amaçlıdır. NPU'nun INT8/FP16 birimleri için GNN sparsity pattern'lerini dikkate alan quantization teknikleri geliştirilmelidir.

4. **Enerji Verimliliği için Heterojen Zamanlama**: CPU-GPU-NPU üçlüsü arasında GNN inference'ın enerji verimliliğini maksimize edecek dinamik zamanlama algoritmaları yoktur.

5. **Standart GNN Benchmark'ı**: MLPerf içinde GNN için resmi bir benchmark kategorisi oluşturulmalıdır.

### Önerilen Araştırma Yönleri

- **GNN-NPU Co-Design**: GNN modelleri ve NPU mimarilerinin birlikte tasarımı (model mimarisi + donanım optimizasyonu)
- **Graph Streaming**: Büyük graph'ların NPU'nun sınırlı belleğine sığdırılması için streaming-based yaklaşımlar
- **Adaptive Sparsity**: Graph sparsity seviyesine göre NPU/CPU/GPU seçimi yapan adaptive inference sistemleri
- **NPU Graph Compiler**: Graph operasyonlarını NPU'nun native instruction set'ine en iyi şekilde derleyen özel derleyici optimizasyonları

Bu literatür tarama rehberi, Intel Core Ultra NPU üzerinde GNN çalıştırma konusunda mevcut bilgi birikimini ve gelecekteki araştırma fırsatlarını sistematik bir şekilde ortaya koymaktadır.

**Intel Core Ultra serisi NPU (özellikle Meteor Lake ve Lunar Lake) üzerinde Graph Neural Network (GNN) modellerinin deploy edilmesi, performans ve enerji verimliliği benchmark’ı**, edge AI’nin yükselişiyle kritik bir konu. GNN’ler irregular/sparse graph yapıları nedeniyle standart DNN accelerator’ları (NPU’lar dahil) için zorlayıcıdır; aggregation (message passing) aşaması yüksek sparsity içerirken, update aşaması daha dense olabilir. Bu rehber, literatürü belirtilen başlıklar altında organize eder ve her biri için seminal eserleri, 2022-2025 (ve 2026 başı) öne çıkan çalışmaları, araştırma boşluklarını ve yanıtsız soruları vurgular.

Literatür taraması için öneriler:

- **Anahtar kelimeler**: "GNN acceleration NPU", "GraNNite Intel NPU", "GNN OpenVINO", "Graph Neural Network edge inference energy", "sparse GNN FPGA/ASIC", "Intel Core Ultra NPU architecture".

### 1. GNN MODELLERİ VE MİMARİLERİ

**Temel GNN modelleri (GCN, GAT, GraphSAGE, GIN, SGC)**:  
Seminal eserler:  
- **GCN**: Kipf & Welling, "Semi-Supervised Classification with Graph Convolutional Networks" (2017, arXiv:1609.02907) — spektral yaklaşımdan spatial message passing’e geçiş.
- **GAT**: Veličković et al., "Graph Attention Networks" (2018) — attention mekanizmasıyla komşu ağırlıklandırma.
- **GraphSAGE**: Hamilton et al., "Inductive Representation Learning on Large Graphs" (2017) — sampling + aggregation ile inductive öğrenme ve ölçeklenebilirlik.
- **GIN**: Xu et al., "How Powerful are Graph Neural Networks?" (2019) — Weisfeiler-Lehman testine yakın expressive power.
- **SGC**: Wu et al., "Simplifying Graph Convolutional Networks" (2019) — lineer approximation ile hızlandırma.

**Hafif/edge-uyumlu GNN varyantları**: Pruning, quantization ve sampling tabanlı modeller (örneğin LightGNN, Degree-Quant). Güncel çalışmalar quantization ve pruning’in GNN’lerdeki etkisini inceliyor (2025 çalışmaları: unstructured pruning %50 boyut küçültme ile accuracy koruma veya iyileştirme).

**GNN operasyonlarının hesaplama profili (sparse vs dense)**: Aggregation genellikle ultra-sparse SpMM/SpMV (adjacency matrix), update dense matris-vekter çarpımları. Bu heterojenlik, DNN accelerator’larını zorlar.

**2022-2025 öne çıkan çalışmalar**: Comprehensive surveys on GNN variants; pruning/quantization impact on GNNs (2025); lightweight edge GNN’ler (pruning + knowledge distillation hibritleri).

**Araştırma boşlukları ve yanıtsız sorular**: Çoğu çalışma homojen graph’lar veya küçük dataset’ler (Cora, CiteSeer) üzerine; gerçek-world heterojen, dinamik graph’larda (sosyal ağlar, moleküler dinamikler) edge-uyumlu varyantların genelizability’si zayıf. **Yanıtsız**: Intel NPU’nun fixed data shapes ve sınırlı sparsity desteğinde hangi GNN mimarisi (örneğin GAT attention vs GIN sum) en iyi trade-off’u verir? Dynamic graph’larda sampling overhead’i NPU’da nasıl minimize edilir?

### 2. NPU VE EDGE AI DONANIM MİMARİLERİ

**Genel NPU mimarileri ve tasarım felsefesi**: NPU’lar düşük güçte yüksek TOPS için tasarlanmış, çoğunlukla systolic array veya MAC-heavy mimarilerle DNN’lere (özellikle CNN/Transformer) optimize. Temel felsefe: dataflow optimization, quantization-friendly (INT8/FP16), düşük precision arithmetic.

**Intel Core Ultra NPU mimarisi (Meteor Lake / Lunar Lake)**:  
- **Meteor Lake** (Core Ultra Series 1): İki neural compute engine, ~10-11 TOPS (INT8/FP16), Movidius tabanlı LEON çekirdekler; DPU FP32 desteklemez. Toplam platform ~34 TOPS.
- **Lunar Lake** (Core Ultra 200V Series): NPU 4 mimarisi, 6 neural core engine, ~48 TOPS INT8 (platform toplamı 120 TOPS’a kadar); daha yüksek clock, güç verimliliği odaklı. Microsoft Copilot+ gereksinimlerini karşılar (≥40 TOPS).

**DNN accelerator’ların GNN için sınırlılıkları**: DNN accelerator’ları dense, düzenli computation için optimize; GNN’lerin irregular sparse aggregation’ı load imbalance, poor data locality ve düşük utilization’a yol açar. Sparse matrix’ler (adjacency) ile dense feature matrix’lerin karışımı, mevcut systolic arrays veya vector units’ı verimsiz kılar.

**2022-2025 öne çıkan çalışmalar**: Intel’in NPU dokümanları ve Lunar Lake whitepaper’ları; genel edge AI benchmark’ları (NPU vs CPU/GPU enerji karşılaştırmaları).

**Araştırma boşlukları ve yanıtsız sorular**: Intel NPU’ya özel micro-architectural detaylar (memory hierarchy, sparsity handling) sınırlı erişilebilir. **Yanıtsız**: Meteor Lake vs Lunar Lake NPU’larda GNN için hangi dataflow (push/pull aggregation) daha iyi? NPU’nun static shape kısıtlaması dinamik graph batching’i nasıl etkiler? Gerçek güç/enerji ölçümlerinde (sustained inference) thermal throttling etkisi nedir?

### 3. GNN DONANIM HIZLANDIRMA

**FPGA tabanlı GNN accelerator’lar**: FP-GNN (2022, adaptive FPGA), LL-GNN (2024, low latency için LHC), AutoGNN (2026, preprocessing bottleneck’ları çözen FPGA). Reconfigurability sayesinde sparsity ve irregularity’ye uyum sağlar.

**ASIC tabanlı GNN accelerator’lar**: GRIP, GReTA gibi custom mimariler; sparse-dense hybrid dataflow’lar.

**COTS cihazlarda GNN**: GPU’lar (cuSPARSE iyileştirmeleri) ve CPU’lar yaygın; ancak enerji verimsiz.

**NPU üzerinde GNN (GraNNite ve benzeri)**: **GraNNite** (2025, Arghadip Das et al., Intel bağlantılı) — ilk hardware-aware framework; COTS DNN accelerator’lar (NPU) için GNN optimizasyonu. GraphSplit, EffOps, QuantGr gibi tekniklerle CPU/GPU’ya göre 10.8× / 6.7× performans, daha iyi enerji. NPU sparsity handling, static shapes ve quantization’u hedefler.

**2022-2025 öne çıkan çalışmalar**: GNN hardware survey’leri (2021-2024); FP-GNN, LL-GNN, GraNNite; preprocessing accelerator’lar (KAIST AutoGNN).

**Araştırma boşlukları ve yanıtsız sorular**: Çoğu çalışma FPGA/ASIC prototipler; COTS NPU’larda (özellikle Intel) production-level deployment az. **Yanıtsız**: GraNNite benzeri optimizasyonlar farklı GNN modelleri (GAT attention-heavy vs GCN) ve graph tiplerinde ne kadar genelleşir? Intel NPU’da multi-model concurrent execution veya dynamic graph’larda scalability? Uzun vadeli reliability (aging, thermal) etkileri?

### 4. DEPLOYMENT VE OPTİMİZASYON TEKNİKLERİ

**Model quantization (INT8, FP16) GNN için**: GNN’lerde aggregation-aware quantization (A²Q), Degree-Quant; pruning + quantization hibritleri accuracy kaybını sınırlı tutar (2025 çalışmaları). NPU’lar INT8/FP16’ya iyi uyar ancak GNN sparsity’si ekstra kazanç sağlar.

**Graph sparsity exploitation**: Sparse matrix formatları (CSR), reordering, clustering; NPU’da etkili sparsity handling kritik.

**Operator fusion ve graph batching**: Fusion (aggregation + update), mini-batch veya graph sampling (GraphSAGE stili).

**OpenVINO ile GNN deployment**: Intel’in resmi toolkit’i; NPU plugin, NNCF (Neural Network Compression Framework) ile quantization/pruning, graph extension API. FP16/INT8 desteği; dynamic shapes sınırlı iyileşmeler var (2025-2026 release’lerde). GraNNite ile entegre edilebilir.

**2022-2025 öne çıkan çalışmalar**: Pruning/quantization impact on GNN (2025); OpenVINO NNCF + sparsity; GraNNite optimizasyonları (GraphSplit vb.).

**Araştırma boşlukları ve yanıtsız sorular**: GNN quantization genellikle node/edge-specific; global quantization kalitesi değişken. **Yanıtsız**: OpenVINO + Intel NPU’da GNN için en iyi quantization pipeline (PTQ vs QAT, group-wise vs channel-wise) hangisi? Sparsity + quantization kombinasyonunun gerçek enerji kazancı (mJ/inference) ne kadar? Dynamic graph’larda fusion overhead’i?

### 5. BENCHMARK METODOLOJİSİ

**Donanım benchmark metodolojileri**: Latency, throughput, power, energy (mJ/inference veya TOPS/W); sustained vs burst; thermal etkiler.

**GNN inference benchmark çalışmaları**: MLPerf Inference’te RGAT gibi GNN workload’ları eklendi (v5.0+); edge platform karşılaştırmaları (NPU üstün enerji verimliliği).

**Enerji verimliliği ölçüm yöntemleri**: Wattmetre, Intel Power Gadget, software-based (perf + RAPL); MLPerf Power submissions.

**MLPerf ve benzeri standart benchmark’lar**: MLPerf Inference (edge/datacenter, yeni GNN’ler); PalmBench, MELT gibi edge AI benchmark’ları. NPU’lar enerji açısından CPU/GPU’yu geçer.

**2022-2025 öne çıkan çalışmalar**: Edge AI benchmarking (2024); MLPerf v5.x; NPU vs GPU/CPU enerji karşılaştırmaları (NPU 35-70% daha az güç).

**Araştırma boşlukları ve yanıtsız sorular**: Standart GNN benchmark’ları sınırlı (küçük graph’lar, statik). **Yanıtsız**: Intel Core Ultra NPU’da gerçek-world GNN benchmark’ları (büyük, heterojen graph’lar) eksik; reproducible enerji ölçümü metodolojisi (ambient temperature, workload mix) standartlaşmadı. GraNNite ile optimize edilmiş modellerin MLPerf-like submission’ı var mı?

### 6. KARŞILAŞTIRMALI ANALİZ ÇALIŞMALARI

**CPU vs GPU vs NPU karşılaştırmaları**: NPU’lar enerji verimliliğinde üstün (özellikle sustained inference); GPU throughput’ta önde ancak güç tüketimi yüksek. GraNNite: NPU GNN için CPU’ya 10.8×, GPU’ya 6.7×更快 +更好 enerji.

**Edge cihazlarda AI inference karşılaştırmaları**: NPU tabanlı sistemler (Intel, Qualcomm, AMD) vs GPU/CPU; heterogeneous execution (CPU+GPU+NPU).

**2022-2025 öne çıkan çalışmalar**: Benchmarking Edge AI Platforms (2024); NPU efficiency papers (2025); GraNNite karşılaştırmaları; MLPerf edge sonuçları.

**Araştırma boşlukları ve yanıtsız sorular**: Çoğu karşılaştırma toy dataset’ler veya single-model; multi-task, real-time edge senaryoları az. **Yanıtsız**: Lunar Lake NPU ile Meteor Lake karşılaştırmasında GNN enerji-per-inference kazancı ne kadar? Farklı graph scale’lerde (küçük vs büyük) NPU utilization drop’u nasıl? Gerçek uygulamalarda (recommendation, drug discovery) end-to-end latency/energy trade-off’ları?

**Genel Tavsiyeler ve Boşluklar**:  
Alan hızla büyüyor ancak Intel NPU’ya özel GNN çalışmaları sınırlı (GraNNite öncü). Boşluklar: gerçek-world büyük/heterojen/dinamik graph’lar, production deployment (OpenVINO + GraNNite entegrasyonu), uzun vadeli enerji/thermal analiz, multi-modal GNN’ler (graph + text/image).  
Yanıtsız ana sorular: Intel NPU’nun mimari kısıtlamalarında (sparsity, memory) optimal GNN design space nedir? Quantization + sparsity + fusion kombinasyonuyla ulaşılabilir maksimum enerji verimliliği (örneğin tokens/joule veya inferences/mJ) ne? Bu konu için deneysel çalışma (GraNNite + OpenVINO + Lunar Lake benchmark’ı) yüksek etki potansiyeline sahip.

Bu rehberi temel alarak literatürü genişletin; arXiv’de "GNN NPU" aramalarını ve Intel developer forumlarını takip edin. Deneysel çalışmada PyG → ONNX/OpenVINO conversion + NNCF + custom GraNNite-like optimizasyonları deneyin. Başarılar!

**OpenVINO ile GNN Optimizasyonları (Intel Core Ultra NPU Odaklı Detaylı Rehber)**

OpenVINO, Intel’in resmi inference toolkit’idir ve özellikle **Intel Core Ultra serisi NPU** (Meteor Lake / Lunar Lake) üzerinde yüksek performanslı, düşük enerjili deployment için tasarlanmıştır. Ancak **Graph Neural Networks (GNN)**, irregular sparsity, dynamic neighbor aggregation ve control-heavy operasyonları nedeniyle standart DNN’lerden (CNN/Transformer) daha zorlayıcıdır. OpenVINO bu alanda **doğrudan tam GNN desteği** sunmaz; optimizasyonlar çoğunlukla **PyTorch Geometric (PyG) → ONNX/OpenVINO IR** conversion + **NNCF** (Neural Network Compression Framework) + **custom teknikler** üzerinden yapılır.

En önemli referans çalışma: **GraNNite** (2025, Arghadip Das et al.) — Intel NPU’lar üzerinde GNN çalıştırmak için geliştirilen ilk hardware-aware framework. Modeller PyTorch/PyG ile eğitildikten sonra **OpenVINO formatına** dönüştürülerek NPU’da çalıştırılıyor ve GraNNite optimizasyonları (GraphSplit, EffOp, QuantGr vb.) uygulanarak **CPU’ya göre 10.8×**, **GPU’ya göre 6.7×** performans + önemli enerji kazancı elde ediliyor.

### 1. Genel Deployment Pipeline (PyG → OpenVINO NPU)

1. **Model Eğitimi**: PyTorch + PyTorch Geometric (PyG) veya DGL ile GCN, GAT, GraphSAGE, GIN vb. modelleri eğit.
2. **Conversion**:
   - `torch.onnx.export()` ile ONNX’e aktar (dynamic axes dikkat!).
   - `openvino.convert_model()` veya Model Optimizer (mo.py) ile OpenVINO IR (.xml + .bin) formatına dönüştür.
3. **NPU Deployment**:
   ```python
   import openvino as ov
   core = ov.Core()
   model = core.read_model("model.xml")
   compiled_model = core.compile_model(model, device_name="NPU")  # veya "AUTO"
   ```
4. **Benchmark**: `benchmark_app` aracı ile latency, throughput ve enerji ölçümü (HWINFO veya Intel Power Gadget ile).

**Önemli Uyarı**: NPU’da **dynamic shapes** desteği sınırlıdır (2025-2026 sürümlerinde iyileşiyor). GNN’lerin değişken node/edge sayısı nedeniyle **static shape** zorlaması yaygındır.

### 2. Temel Optimizasyon Teknikleri (NNCF ile)

**NNCF**, OpenVINO’nun en güçlü optimizasyon aracıdır ve GNN’ler için şu yöntemleri destekler:

- **Post-Training Quantization (PTQ)**: En basit ve etkili. ~300 kalibrasyon örneği ile INT8’e düşürür. GNN’lerde aggregation (sparse) ve update (dense) kısımlarını ayrı ayrı dikkate almak faydalıdır. Accuracy kaybı genellikle %1-3 arasındadır; fine-tuning ile düzeltilir.
- **Quantization-Aware Training (QAT)**: Eğitim sırasında quantization simüle edilir. Daha yüksek doğruluk, ancak daha uzun süre alır.
- **Pruning**:
  - Unstructured / fine-grained pruning: %50 model boyutu küçültme ile accuracy korunabilir veya artabilir (2025 GNN pruning çalışmaları).
  - Structured / filter pruning: Daha agresif hız kazancı, ancak GNN katmanlarında dikkatli uygulanmalı.
- **Joint Pruning + Quantization + Distillation (JPQD)**: Transformer’lar için geliştirilen yöntem; GNN’lerde de uyarlanabilir. Tek pipeline’da birden fazla sıkıştırma uygular.

**GNN’ye Özel Etkiler** (2025 arXiv çalışması):
- Unstructured/global pruning + fine-tuning ile model boyutu %50 azalırken accuracy korunur veya iyileşir.
- Quantization yöntemleri (INT8, FP16) dataset ve modele göre değişken etki gösterir (Cora, Proteins, BBBP üzerinde test edilmiş).
- Inference time, memory ve enerji tüketiminde belirgin iyileşme.

### 3. GNN’ye Özel Optimizasyonlar (GraNNite ve Benzeri)

GraNNite, OpenVINO üzerinde çalışan GNN’leri hedefleyerek şu teknikleri sunar:

- **GraphSplit**: Workload’u NPU ve CPU/GPU arasında akıllıca dağıtır (irregular kısımlar CPU’ya).
- **StaGr / NodePad**: Static graph aggregation ve node padding (değişken node sayısını sabitlemek için padding ekleme, örneğin Cora’da 2708 → 3000 node).
- **GraphSAGE Sampling**: Komşu sayısını sınırlama (örneğin max 10 neighbor).
- **EffOp (Efficient Operators)**: Control-heavy operasyonları optimize eder.
- **GraSp**: Sparsity exploitation (adjacency matrix’in sparse yapısını daha iyi kullanma).
- **QuantGr**: GNN-specific INT8 quantization.
- **GrAx serisi**: Attention, broadcast-add ve SAGE-max aggregation için özel optimizasyonlar.

**Sonuçları (Intel Core Ultra NPU’larda)**:
- Default NPU mapping’e göre **2-7×** speedup.
- Lunar Lake (Series 2) Meteor Lake’e (Series 1) göre **~1.7×** daha yüksek throughput.
- Enerji verimliliği CPU/GPU’ya göre **6-8×**’e varan iyileşme.

Bu optimizasyonlar **OpenVINO benchmark_app** ile ölçülmüş ve reproducible kodlar paylaşılmıştır.

### 4. Sparsity Exploitation ve Operator Fusion

- **Graph sparsity**: Adjacency matrix genellikle çok sparse’tır. OpenVINO’nun graph optimization passes’ı (fuse operations) dense matris çarpımlarını iyi optimize eder, ancak sparse SpMM için ekstra çaba gerekir (GraSp gibi).
- **Operator Fusion**: Aggregation + linear update + activation gibi ardışık işlemleri birleştirir. NPU’da bu, memory access’i azaltır.
- **Batching**: Mini-batch graph’lar veya sampled subgraphs. Dynamic batching NPU’da sınırlı desteklenir (2025+ sürümlerde iyileşme var).

### 5. Zorluklar ve Araştırma Boşlukları / Çözüm Önerileri

- **Dynamic Shapes Sorunu**: GNN’ler için node/edge sayısı değişkendir. Çözüm:
  - **Node Padding** (NodePad): Input’u sabit boyuta getir (örneğin max node sayısına pad et).
  - Dynamic shapes desteği NPU’da sınırlı; fallback CPU’ya olabilir. 2026 sürümlerinde dynamic batch ve reshape iyileştirmeleri var.
- **Unsupported Operations**: Bazı GNN-specific ops (custom scatter/gather, sparse attention) OpenVINO’da native desteklenmeyebilir → **Custom Operations / Extensions** API’si ile C++/Python’da implement et.
- **Sparsity Handling**: NPU’lar dense computation’a optimize; sparsity düşük utilization’a yol açar. GraNNite’in GraSp ve GraphSplit’i burada kritik.
- **Accuracy-Energy Trade-off**: Quantization + pruning sonrası accuracy drop’unu GNN-specific metriclerle (node classification F1, link prediction AUC) ölç.
- **Heterojen Execution**: NPU + CPU + GPU birlikte kullan (OpenVINO AUTO device veya manual partitioning).

**2025-2026 Güncel Durum**:
- OpenVINO 2025.x / 2026.x sürümlerinde NPU plugin iyileştirmeleri, dynamic shapes desteği ve LLM/GNN hibrit modeller için gelişmeler var.
- Knowledge Graph’ler (ConvE gibi) için özel örnekler mevcut; tam GNN için GraNNite öncü konumda.

### Pratik Tavsiyeler (Deneysel Çalışma İçin)

1. Küçük dataset’lerle başla (Cora, Citeseer) → GCN/GAT/GraphSAGE modelleri.
2. PyG → ONNX → OpenVINO IR conversion yap, hataları custom op’larla çöz.
3. NNCF ile PTQ/QAT + pruning uygula.
4. GraNNite tekniklerini (NodePad, sampling limit, QuantGr) manuel olarak uyarla veya kodunu incele.
5. Benchmark: `benchmark_app -d NPU -m model.xml` + enerji ölçümü (HWINFO).
6. Karşılaştırma: Aynı modelde CPU vs NPU vs GPU latency/energy.

**Yanıtsız Sorular / Boşluklar**:
- Farklı GNN mimarilerinde (attention-heavy GAT vs basit GCN) OpenVINO + NPU optimizasyonlarının genelleme gücü nedir?
- Gerçek-world büyük/heterojen/dinamik graph’larda (milyonlarca node) NodePad + sparsity kombinasyonunun pratik limiti ne?
- OpenVINO custom op’larla tam sparse SpMM desteği ne kadar iyileştirilebilir?
- Multi-task veya streaming GNN’lerde (dinamik graph update) sustained enerji verimliliği nasıl olur?

Bu optimizasyonlarla Intel Core Ultra NPU’lar, edge’de GNN inference için oldukça rekabetçi hale geliyor — özellikle **enerji verimliliği** açısından. Daha spesifik bir model (örneğin GAT) veya adım (quantization pipeline) için detay istersen söyle, kod örnekleri veya ek literatür önerebilirim.

**Kaynaklar**: OpenVINO docs (NNCF, NPU plugin), GraNNite arXiv (2025), ilgili Intel community ve release notes. Güncel OpenVINO sürümünü (2025.3+) ve en son NPU driver’ını kullanmayı unutma.


**GraNNite Teknikleri Detaylı Anlatım**

**GraNNite**, 2025 yılında Arghadip Das ve Intel/Purdue ekibi tarafından geliştirilen, **Intel Core Ultra serisi NPU** (Meteor Lake / Lunar Lake) gibi ticari DNN accelerator’ları üzerinde **Graph Neural Network (GNN)** inference’ını optimize etmek için tasarlanmış ilk hardware-aware framework’tir. 

Temel amacı: GNN’lerin irregular memory access, yüksek sparsity, dynamic graph yapısı ve control-heavy operasyonlarından kaynaklanan sorunları çözerek, **OpenVINO** üzerinden NPU’da verimli çalıştırmaktır.

**Üç Aşamalı Metodoloji**:
1. **Enabling NPU Execution** — GNN’leri NPU’da çalıştırılabilir hale getirme (dynamic shapes ve unsupported ops sorunlarını çözme).
2. **Performance Optimization** — Latency ve throughput iyileştirme.
3. **Accuracy-Efficiency Trade-off** — Quantization ve approximation teknikleriyle enerji/performans kazancı.

### GraNNite’in Ana Teknikleri

GraNNite, GNN katmanlarını üç temel tipe ayırır: **GraphConv**, **GraphAttn** (Attention) ve **SAGE** (Sample & Aggregate). Her biri için özel optimizasyonlar geliştirilmiştir.

#### 1. Enabling Stage (NPU Çalıştırma Teknikleri)
- **GraphSplit**:  
  Workload’u akıllıca böler. Irregular ve preprocessing-heavy kısımlar (graph construction, neighbor sampling, adjacency matrix hazırlama) **CPU**’ya verilirken, data-parallel ve compute-intensive kısımlar (aggregation + update) **NPU**’ya aktarılır. Bu, NPU’nun güçsüz olduğu control-flow ve irregular access’leri azaltır.

- **StaGr (Static Graph Aggregation)**:  
  Statik graph’lar için aggregation aşamasını önceden optimize eder. Graph yapısını sabitler ve NPU’nun memory hierarchy’sine daha uygun hale getirir.

- **NodePad**:  
  Değişken node/edge sayısını (dynamic shapes) çözmek için **node padding** uygular. Örneğin, bir batch’teki maksimum node sayısına göre tüm graph’ları pad eder. Bu, NPU’nun tercih ettiği fixed/static input shape’leri sağlar. Padding overhead’i minimize etmek için akıllı padding stratejileri kullanılır.

- **GrAd (Graph Adapter / Dynamic Update)**:  
  Dinamik graph’lar (real-time edge/node ekleme/çıkarma) için hızlı güncelleme mekanizması. Özellikle event-driven vision veya streaming graph uygulamalarında faydalıdır.

#### 2. Performance Optimization Stage
- **EffOp (Efficient Operators)**:  
  GNN’lerdeki control-heavy operasyonları (scatter, gather, indexing, conditional logic) NPU-friendly hale getirir. OpenVINO IR seviyesinde operator fusion ve custom implementation’larla overhead azaltılır.

- **GraSp (Graph Sparsity Exploitation)**:  
  Adjacency matrix’in ultra-sparse yapısını daha iyi kullanır. NPU’nun dense-oriented mimarisine rağmen sparsity’yi exploit ederek memory bandwidth ve computation’ı optimize eder. Sparse matrix formatları (CSR vb.) ve reordering teknikleri entegre edilir.

- **PreG ve SymG (Graph Convolution’a özel)**:  
  - **PreG**: Graph Convolution katmanlarındaki redundancy’leri (tekrarlanan hesaplamaları) önceden ele alır.
  - **SymG**: Symmetric graph’lar için özel optimizasyon (simetriyi kullanarak computation’ı yarıya indirme).
  - **CacheG**: Memory transferlerini azaltmak için caching stratejileri.

#### 3. Accuracy vs Efficiency Trade-off Stage
- **QuantGr**:  
  GNN-specific **INT8 quantization**. Standart PTQ/QAT’ten farklı olarak, aggregation (sparse) ve feature update (dense) kısımlarını ayrı ayrı dikkate alır. Accuracy kaybını minimize ederken memory footprint ve computation süresini önemli ölçüde düşürür.

- **GrAx Serisi (GNN-specific Approximations)**:
  - **GrAx1**: Graph Attention mekanizması için optimizasyon (attention skorlarının hesaplanmasını hızlandırır, softmax vb. işlemleri approximation ile optimize eder).
  - **GrAx2**: Broadcast-add operasyonları için (özellikle residual bağlantılar ve feature birleştirmelerde).
  - **GrAx3**: SAGE-max aggregation (Sample and Aggregate’daki max-pooling) için özel optimizasyon. Max operasyonunun NPU’da verimli çalışmasını sağlar.

Bu teknikler birlikte uygulandığında:
- **Default NPU mapping**’e göre **2.6× – 7.6×** speedup.
- **CPU**’ya göre **10.8×** performans + önemli enerji kazancı.
- **GPU**’ya göre **6.7×** performans.
- **Enerji verimliliği** iyileşmesi **8.6×**’e kadar çıkabiliyor.
- **Lunar Lake (Core Ultra Series 2)**, **Meteor Lake (Series 1)**’e göre yaklaşık **1.7×** daha yüksek throughput sağlar.

### GraNNite ile Pratik Kullanım (OpenVINO Entegrasyonu)

1. PyTorch Geometric (PyG) ile modeli eğit.
2. Modeli ONNX → OpenVINO IR formatına dönüştür.
3. GraNNite optimizasyonlarını uygula (GraphSplit, NodePad, QuantGr vb. — kod repository’sinde script’ler mevcut).
4. `ov.compile_model(..., device="NPU")` ile çalıştır.
5. `benchmark_app` ile ölçüm yap (latency, throughput, energy).

**Desteklenen Dataset’ler (orijinal repo)**: Cora, Citeseer, PubMed (küçük-orta ölçekli node classification).

**Kod**: https://github.com/arghadippurdue/GraNNite (train, convert, inference script’leri içerir).

### Araştırma Boşlukları ve Yanıtsız Sorular

- Teknikler ağırlıklı olarak **küçük/orta ölçekli statik graph’lar** (Cora vb.) üzerinde test edilmiş. Milyonlarca node’lu gerçek-world graph’larda (örneğin sosyal ağlar, büyük knowledge graph’ler) scalability nasıl olur?
- **Dynamic graph’larda** (sürekli değişen edge’ler) NodePad + GrAd kombinasyonunun overhead’i ne kadar artar?
- **Attention-heavy modeller** (GAT, RGAT) ile **basit GCN** arasında optimizasyon etkinliği nasıl farklılaşır?
- **Multi-task** veya **heterojen execution** (NPU + CPU + GPU aynı anda) senaryolarında GraNNite’in partitioning stratejisi ne kadar etkili?
- **Daha büyük GNN mimarileri** (Graph Transformer’lar, multi-modal GNN’ler) veya LLM + GNN hibritlerinde (RAG backend) performans nasıl olur?
- Quantization’ın (QuantGr) çok derin GNN’lerdeki cumulative accuracy kaybı henüz yeterince incelenmemiş.

**Pratik Tavsiye**:  
Başlangıç için Cora dataset’inde GCN/GAT/GraphSAGE modellerini deneyin. Önce temel OpenVINO conversion + NNCF PTQ yapın, ardından GraNNite tekniklerini tek tek ekleyerek kazancı ölçün. Lunar Lake sistemde test etmek en iyi sonuçları verir.

Daha spesifik bir teknik (örneğin GraphSplit implementasyonu, QuantGr detayları veya kod örnekleri) istersen, ya da belirli bir GNN modeli (GAT vs GCN) üzerinde karşılaştırma istiyorsan söyle, daha derin gidebiliriz.

**Ana Kaynak**:  
- ArXiv: https://arxiv.org/abs/2502.06921 (GraNNite paper, 2025)  
- Intel video ve developer kaynakları (NPU üzerinde GNN optimizasyonu).

Bu teknikler, Intel Core Ultra NPU’ları edge GNN inference için gerçekten rekabetçi hale getiriyor. Başarılar!

**Konu:** *Intel Core Ultra NPU üzerinde Graph Neural Network (GNN) modellerinin çalıştırılması ve performans / enerji verimliliği benchmark analizi*

***

## 1. GNN MODELLERİ VE MİMARİLERİ

### 1.1. Temel (Seminal) GNN Modelleri

Bu çalışmalar GNN literatürünün temelini oluşturur ve **donanım analizi açısından “hangi operasyonlar gerçekten kritik?” sorusuna cevap verir.**

*   **GCN – Kipf & Welling (2017)**  
    *Semi-Supervised Classification with Graph Convolutional Networks*
    *   Lineer cebir ağırlıklı (sparse-dense matmul)
    *   Donanım dostu olmasına rağmen memory-bound

*   **GraphSAGE – Hamilton et al. (2017)**
    *   Sampling tabanlı → edge cihazlar için ölçeklenebilirlik
    *   Düzensiz bellek erişimi

*   **GAT – Veličković et al. (2018)**
    *   Attention mekanizması → NPU’lar için zorlayıcı
    *   Softmax + adjacency traversal

*   **GIN – Xu et al. (2019)**
    *   Expressiveness yüksek
    *   MLP yoğunluğu fazla → compute-heavy

*   **SGC – Wu et al. (2019)**
    *   Önceden hesaplanmış propagasyon
    *   NPU inference için en uygun adaylardan biri

**Donanım açısından kritik nokta:**

> GNN’lerde performans genellikle *aggregation + memory access* tarafından belirlenir, değil FLOP sayısı.

***

### 1.2. Hafif / Edge‑Uyumlu GNN Varyantları

(Edge ve NPU çalışmaları için öncelikli okuma)

*   **Simplifying GNNs (SGC, GAMLP, SIGN)**
*   **SparseGNN / Tail-GNN**
*   **Quantized GNNs (QGNN)**

**2022–2025 öne çıkanlar:**

*   SIGN tabanlı inference hızlandırma çalışmaları
*   Lightweight attention-free GNN varyantları
*   Mini-batch ve subgraph-based inference

**Research Gaps**

*   Edge-GNN’lerde **accuracy–latency–energy üçlü optimizasyonu** hâlâ tam çözümlenmiş değil
*   NPU-friendly GNN mimarisi tanımı yok

***

### 1.3. GNN Operasyonlarının Hesaplama Profili

**Bu kısım tezinin mimari katkısı için ÇOK KRİTİK.**

| Operasyon       | Karakteristik        |
| --------------- | -------------------- |
| Message Passing | Sparse, irregular    |
| Aggregation     | Memory-bound         |
| MLP / Update    | Dense, compute-bound |
| Attention       | Control-heavy        |

**Açık Sorular**

*   NPUs dense için optimizeyken sparse workload nasıl haritalanmalı?
*   Sparse adjacency → dense tensor dönüşümü enerji açısından mantıklı mı?

## 2. NPU VE EDGE AI DONANIM MİMARİLERİ

### 2.1. Genel NPU Mimarileri

Örnekler:

*   Google Edge TPU
*   Apple ANE
*   Qualcomm Hexagon

***

### 2.2. Intel Core Ultra NPU (Meteor Lake / Lunar Lake)

**Genel Özellikler**

*   INT8 / FP16 öncelikli
*   Dense tensor workload için tasarlanmış
*   OpenVINO ile erişim

**Önemli Nokta:**  
Intel NPU **GNN’ler için doğal olarak optimize edilmemiştir**, ama:

*   Quantized MLP
*   Fused operators  
    gibi bileşenler avantajlıdır.

**2023–2025 döneminde eksik olan:**

> Intel NPU üzerinde **akademik GNN benchmark’ı neredeyse yoktur.**

➡️ **Bu senin en büyük fırsat alanın.**

***

### 2.3. DNN Accelerator’ların GNN İçin Sınırlılıkları

*   Sparse memory access desteği zayıf
*   Düzensiz graph traversal
*   Low arithmetic intensity

**Araştırma boşluğu**

*   DNN accelerator ≠ GNN accelerator
*   NPU’lar GNN için *“emulate edilerek”* kullanılıyor
